Technical architecture & product specification

An EV charging platform built for Indonesian law

The generic CSMS is commoditised. What no international vendor has — and no local player has yet productised — is the Indonesian compliance and commercial layer. That is the whole product thesis.

Brand PlugSure · plugsure.com Hardware Autel MaxiCharger Protocol OCPP 1.6J → 2.0.1 Status spec + running scaffold

01The thesis

Why an Indonesia-specific CSMS beats a better generic one.

PlugSure is a multi-tenant Charging Station Management System for Indonesian charge point operators, fleet depots and white-label partners operating under a licence holder's umbrella. AMPECO, Monta and Driivz already do real-time monitoring, load management, RBAC and OCPP well. Competing on those features is competing on a commodity.

Eight capabilities are difficult for a foreign vendor to build and unattractive for them to maintain. Together they are the moat.

Why the gateway is split out

Not because its domain differs — because its lifecycle does. A deploy of the billing code must never drop 4,000 charger WebSockets. It also scales on connection count while the API scales on request rate. Everything else stays one deployable: a six-person team shipping in six months does not have the operational budget for twelve services. Module boundaries are what matter; deployment boundaries can follow.

Connection ownership

Each charge point holds one long-lived socket to one gateway node. Nodes register cp:{id} → node:{id} in Redis with a heartbeat-refreshed TTL; commands publish to cmd:{nodeId} and the owning node correlates the reply. Design assumption: any gateway node may die at any moment and the only cost is a reconnect.

07OCPP layer

The traps, and the discipline that avoids them.

Transport

  • Negotiate from Sec-WebSocket-Protocol, preferring ocpp2.1 > ocpp2.0.1 > ocpp1.6. Echo exactly one.
  • Accept version-in-path as a fallback for chargers with broken negotiation, but header negotiation is authoritative.
  • The charge point ID is the last path segment and PlugSure does not get to choose it. Autel's installer app defaults to the unit's serial number when the identity field is left blank — and installers routinely leave it blank.
  • One outstanding CALL per direction. Queue outbound calls; never pipeline. This is the single most common OCPP implementation error.
  • Heartbeat.conf must return currentTime. Chargers set their clock from it; skipping it silently corrupts every downstream billing timestamp.

Security profiles

ProfileTransportCharger authUse
0ws://noneBench only. Never in production.
1ws://HTTP BasicNever internet-facing.
2wss://HTTP BasicProduction baseline. Mandated by the updated OCPP 1.6 certification programme.
3mutual TLSclient certificateTarget for high-value DC sites, v2.
Rotation order — get this wrong and the charger is bricked

Set AuthorizationKey first, then raise SecurityProfile. Accept both old and new keys for a grace window and handle the charger reconnecting with the new credential on the very next connect. The key must be random 16–20 bytes hex-encoded and WriteOnly — never returned in a GetConfiguration response, never stored in plaintext.

Provisioning

On every BootNotification: resolve or park the charge point (a rejected charger retries forever and the installer gets no feedback), resolve its quirk profile, dump all config, diff, then write each differing key.

Degrade, never fail

Record every Rejected / NotSupported into the quirk profile and continue. Autel units are documented to reject MeterValuesSampledData=Energy.Active.Import.Register. Treating a rejected metering key as a fatal provisioning error would strand the fleet.

The vendor quirk registry

Keyed on (vendor, model, firmware) from BootNotification, storing what was learned empirically: which config keys are rejected, which measurands are actually emitted, whether the hardware wants amps or watts, whether GetCompositeSchedule can be trusted, whether TxDefaultProfile on connector 0 propagates, whether remote firmware update works at all.

Build it on day one, not year two. It is what makes adding vendor #2 cost a sprint instead of a rewrite.

Offline tolerance is a requirement, not a nicety

Indonesian sites are predominantly 4G-backhauled with poor fixed-line reliability. Chargers queue transaction messages while offline and replay them on reconnect — out of order and with stale timestamps.

  • Bill on the charger's timestamps, never on receipt time.
  • Key sessions on (chargePointId, connectorId, txRef, startTimestamp) and make CDR generation idempotent.
  • Sync the local auth list aggressively so offline authorisation keeps working.
  • Show connectivity history separately from fault state. A charger that is offline is not necessarily faulted, and support must tell the difference at a glance.

08Autel specifics

Eight risks to close before any fleet commitment.

How you point an Autel at your own backend

Via the Autel Config installer app over Bluetooth LE. The fields are Security Profile, Server IP/Domain, Server Path, Server Port, Chargebox Identity (blank = serial number), plus APN settings on 4G units. The endpoint assembles as wss://<domain>:<port><path><chargeBoxId>.

Autel Config has no public registration — installers must be enrolled Autel partners. Budget for that in procurement. The consumer Autel Charge app exposes an OCPP server list on some builds, but it is often a pre-provisioned whitelist rather than a free-text field. Do not plan on it — but do ask Autel whether PlugSure can be added to that list. If granted, it is a real distribution advantage.

#SeverityRiskAction
1HIGH Enabling third-party OCPP may be irreversible and permanently disables Autostart. Autel support is documented as saying "once your charger takes the 3rd party OCPP configuration there is no way for us to make changes to it." 2HIGH No confirmed Autel presence in Indonesia — no public evidence of a local office, distributor, or SNI/import certification. Identify the distributor, RMA path and certification status before specifying Autel at all.

Architectural instruction

Treat Autel's local dynamic load balancing — external meter and CT clamps over Modbus RS485, master/secondary between units, documented limit of 8 chargers per meter — as the layer that actually guarantees the incoming breaker. Layer OCPP SetChargingProfile on top for tariff- and grid-driven shaping. Never build the site power budget on the assumption that OCPP smart charging alone protects the breaker: the RS485 path works when the WAN is down, and in Indonesia the WAN will be down.

09Tariff & tax

Five layers on a single retail session. None of them is a constant.

1. Energy kWh × rate regulated: N × 1,650 (1.0 ≤ N ≤ 1.5) bulk: Q × 707 (0.8 ≤ Q ≤ 3.0) 2. Service fee per session ceiling Rp 25,000 fast · Rp 57,000 ultrafast 3. Admin fee operator's own e.g. Rp 4,000 4. PBJT up to 10% SET PER KABUPATEN/KOTA — never national 5. PPN 12% on DPP DPP = 11/12 × price → 11% effective

Model the multiplier, not the rate

The widely-quoted retail price of Rp 2,466–2,475/kWh is simply N = 1.5. PLN sets the multiplier by Direksi decision and it varies by scheme, voltage level and period — public sources give the bulk rate as Rp 700, 707, 714 and 1,100 at different dates, which is entirely consistent with a Q multiplier design. The base itself moves too: the Q3-2026 layanan khusus tariff published at Rp 1,645, not 1,650.

Design consequence

Store the base as a versioned, effective-dated value and the multiplier as a per-tenant, per-site configurable. Then add a hard regulatory ceiling layer above operator pricing, validated at save time — so an illegal tariff can never be assigned, rather than being discovered when the invoice is already out.

Get the PPN arithmetic exactly right

The headline rate is 12%, but non-luxury goods and services use DPP nilai lain of 11/12 of the selling price, giving an effective 11%. Compute it as the regulation specifies:

DPP = 11/12 × price → this figure must appear on the faktur pajak PPN = 12% × DPP

Applying 11% directly produces the right total and the wrong DPP, which fails an audit. Getting the arithmetic right but the document wrong is still a failure.

Time of use — build it now, even though it is flat today

WBP (peak) and LWBP (off-peak) blocks exist structurally in the SPKLU tariff schedules, but both are currently priced the same. PLN already applies WBP/LWBP differentials to industrial categories and runs a 30% night discount on home charging — clear policy appetite for temporal signals. Retrofitting time-of-use into a flat-rate engine is expensive; anticipating it is nearly free.

Two rules for tax data

  • PBJT resolves from the site's kabupaten/kota code — which the SPKLU identity number already encodes. Never model it as one national rate.
  • Store every tax field on the transaction, not derived at report time. Rates change; historical invoices must reproduce exactly as issued.
Metrology overrides telemetry

Where the OCPP MeterValues stream and the legally verified meter register diverge, bill from the verified register. StopTransaction.transactionData typically carries the authoritative total; prefer it over the last periodic sample.

10Load management

In Indonesia the ROI is capacity-cost avoidance, not energy arbitrage — and it is quantifiable.

rekening minimum = 40 × connected kVA × block cost payable whether used or not
  1. The minimum monthly bill is set by subscribed capacity, equivalent to 40 hours of full-capacity running. Load management that lets an operator subscribe less kVA reduces the bill floor directly. Expose kVA headroom as a first-class operator metric — it maps to money.
  2. The 200 kVA TR/TM cliff. Above it, the connection moves to 20 kV medium voltage and the customer buys a transformer, switchgear and MV metering. Note the power-factor trap: a 168 kW peak is 177 kVA at PF 0.95 but 210 kVA at PF 0.80 — it crosses the cliff on power factor alone.
  3. Shared building circuits. In Indonesian malls, offices and apartments chargers are almost never on a dedicated supply. Without dynamic balancing against the building's real-time load, they either trip the main or must be throttled to a uselessly conservative static limit.
  4. Genset transfer. Backup gensets are sized for building essentials, not 120 kW of DC charging. Chargers must curtail or stop when the site transfers — which needs a site input signal and an explicit curtailment policy.

Three layers, and only the bottom one guarantees the breaker

Layer 3   PlugSure optimiser        cloud · seconds-to-minutes · revenue, fairness, ToU aware
Layer 2   OCPP SetChargingProfile   survives brief WAN loss via the charger's own copy
Layer 1   charger-local DLB         RS485 CT clamps · works with the WAN down   ← the real guard

Fail-safe behaviour: if the optimiser cannot reach a charger, the charger falls back to a conservatively-set TxDefaultProfile. If the optimiser itself is unhealthy it stops issuing profiles rather than issuing stale ones — a stale ceiling is worse than a conservative one.

Allocation is fair-share water-filling with a minimum-viable floor. When the budget cannot give every session its minimum, shed the lowest-priority sessions entirely rather than starving all of them: a depot of vehicles each drawing 1 kW is worse than half of them charging properly.

11Payments

One constraint shapes everything: the dominant rail cannot hold funds.

At session start the final amount is unknown; payment must be secured before electricity flows. Globally this is solved with a pre-authorisation hold. QRIS has no pre-authorisation and, in its current form, never will — it is a single immediate debit of a fixed amount.

The workaround — charge the maximum then refund — should not be built. Debiting Rp 250,000 to deliver Rp 80,000 of electricity is a conversion killer in a price-sensitive market, refund settlement is slow and issuer-dependent, and a high refund ratio attracts PJP risk-team attention.

The tiered model

TierWhoMechanismWhy
1Registered driverE-wallet tokenisation. Link once at signup; validate at session start; charge the exact final amount server-side at the end. Strictly better UX than pre-auth — one clean transaction for the right amount, no "why is Rp 250,000 pending on my DANA". No hold, no float, no e-money licence. The primary path.
2Premium / fleetCard pre-auth then capture. 7-day hold; capture ≤ authorised. Card penetration is ~35%, so this is a premium path, not a default. First transaction must clear 3DS; recurring needs acquirer approval with real lead time — start that negotiation early.
3Walk-up guest, no app installQRIS pre-purchase. Scan the charger QR → pick Rp 50k / 100k / 150k → the charger delivers exactly that much energy and stops. Inverts the unknown-amount problem instead of fighting it. This is what PLN already does at SPKLU, so it matches driver expectations rather than teaching new ones.
4B2B fleetPostpaid against a dedicated fixed virtual account. Solves Indonesia's reconciliation problem — banks do not reliably expose sender identity, and 60–80% of B2B volume moves by bank transfer.
Board-level, not an implementation detail

Do not build a stored-balance driver wallet without counsel and a licensing plan. Under PBI 20/6/PBI/2018 a closed-loop wallet is exempt from BI licensing only below Rp 1,000,000,000 of float — 10,000 drivers × Rp 100,000 average balance reaches it. Worse: the closed-loop test is whether the payment recipient is the same party that issued the e-money. If a driver tops up a PlugSure balance and spends it on electricity delivered by a third-party site host, a regulator can readily characterise it as open loop — licence required at any float level, exemption inapplicable. This is exactly where the multi-tenant architecture collides with the regulation.

Gateway selection

Xendit primary, Midtrans secondary. Xendit is the only gateway with both capabilities this product needs: e-wallet tokenisation, and xenPlatform native sub-merchant splitting that lets each site host be a sub-merchant with funds split at transaction time and PlugSure's take-rate deducted automatically rather than reconciled after the fact. Midtrans wins on headline price — VA at Rp 4,000 flat against Xendit's Rp 13,000 list is decisive on B2B volume — and its GoPay Mini App is genuine distribution: PlugSure embedded inside GoPay, users auto-logged-in, no setup fee.

A regulatory tailwind worth designing around

From 1 October 2026 Bank Indonesia extends 0% MDR to all merchant categories for transactions ≤ Rp 100,000. At ~Rp 2,466/kWh a 40 kWh session is ~Rp 99,000, and AC destination charging is almost always under the line. Price the QRIS pre-purchase tiers at or below Rp 100,000 deliberately. This also weakens the case for a prepaid wallet — the classic reason to hold balance is amortising per-transaction fees, and that argument largely evaporates along with the reason to take on e-money risk.

e-Faktur

No Indonesian payment gateway issues tax invoices. Invoicing, VAT and e-Faktur are PlugSure's build. Use a PJAP rather than integrating Coretax directly — DJP interfaces change with little notice and this is not where a CPO platform should spend engineering capacity.

A common and expensive design error

A faktur may not be issued to the customer before the serial number (NSFP) returns from Coretax. The invoicing pipeline must treat this as a synchronous dependency with an explicit pending state, not a fire-and-forget async job.

Because a public session is high-volume, low-value and often anonymous, issue e-Faktur on request for B2B, fleet and consumers who need one, and cover retail with simplified documentation — distinguishing B2C from B2B at the transaction level, since their invoicing paths differ.

PlugSure's own receivables: software services are an object of PPh 23 at 2%, so Indonesian corporate customers withhold it from every invoice. It is creditable — cash-flow timing, not lost revenue — but bukti potong must be collected from every customer to claim it. Model receivables net of 2% from day one, and describe the offering consistently as a service: characterising it as a licence or royalty changes the rate to 15%.

The tera regime is the newest and the one no international CSMS models. On 25 May 2026 Kemendag launched type approval and verification for EV charger measuring instruments, classifying EVSE as UTTP — the same regime as fuel dispensers — and targeting phased testing of all operational SPKLU within one year, covering 4,769 EVSE units at launch.

A legal carve-out to design around

Entities that merely lease equipment or perform maintenance in partnership with a licensed provider explicitly do not need WILUS, RUPTL, IUPTLU or an SPKLU identity number. The tenancy model must support a licence-holder umbrella with many sub-operators beneath it.

13Access & data protection

Scoped permissions, a tamper-evident log, and a regulator about to acquire teeth.

RBAC

Permissions are (action, resource) pairs; roles bundle them; assignments are scoped to an organisation, a site or a fleet. A site host gets session:read scoped to their own sites and never sees another host's revenue.

Enforcement belongs at the query layer, not the controller. Every tenant-scoped query goes through a repository that injects the scope predicate. Postgres row-level security is the second line of defence, not the first.

Audit

Append-only and hash-chained per organisation, covering authentication, permission changes, tariff changes with before/after, every remote command issued to a charger and who issued it, token lifecycle, compliance document changes, payment state transitions and data exports. Retained seven years. When a driver calls to ask why their session stopped, support answers in one query.

UU PDP

Fully in force — the transition expired 17 October 2024. Charging data is sensitive in aggregate: identity, location, travel patterns, payment. Obligations to design in: explicit separable consent, purpose limitation, data subject rights, 72-hour breach notification, records of processing, DPIA, and a DPO — likely required, since the platform performs large-scale regular systematic monitoring.

Do not read the absent regulator as absent risk

The Badan PDP has still not been established (target 2026; Kemkomdigi is exercising oversight in the interim), but criminal provisions are enforced by police and prosecutors, not by the data authority. Sanctions run to an administrative fine of 2% of annual revenue and criminal penalties up to 5 years and Rp 5bn. Enforcement capacity is about to increase sharply. Be compliant by design rather than retrofitting under a new regulator's first enforcement wave.

Residency, stated precisely

PP 71/2019 permits private electronic system operators to process and store data outside Indonesia — it relaxed the strict onshore mandate of PP 82/2012. The binding condition is guaranteed access for government supervision, plus declaring data location at registration. Two qualifications: sector rules can override (BI/OJK impose stricter onshore requirements on payment services — routing payments through a licensed PSP avoids inheriting them), and contracting with PLN or government can flow an onshore obligation through contractually.

Host in Jakarta anyway. Four reasons converge: latency to chargers and drivers; removing residency from every enterprise sales conversation; satisfying pass-through obligations; and possibly improving TKDN, since foreign cloud is a foreign-service cost line that dilutes the domestic ratio. Evaluate hosting for TKDN and residency jointly, not separately.

PlugSure is a PSE Lingkup Privat and must register via OSS before the system begins operation. Sanctions escalate to permanent access blocking, which Komdigi has actively used.
