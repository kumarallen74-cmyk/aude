Verdict

Not yet — but the remaining gap is small, named, and mostly configuration.

Three blind audit passes found 100 defects. All criticals and highs are closed and verified against a live stack. What is left is deliberate: a bench-safe default that must be changed before the OCPP port is exposed, a mock payment provider, and no refund rail.

The most important finding in this report is not any individual bug. It is that every remediation pass so far has introduced at least one defect larger than something it fixed.

01The pattern that matters

Read this before the findings.

The most recent regression is the clearest illustration. A change was made to switch Postgres row-level security on — unambiguously a security improvement. It used AsyncLocalStorage.enterWith to bind the tenant to a request. Node pools and reuses HTTPParser objects process-wide, so the store rode a recycled parser out of the HTTP server and into the OCPP gateway's WebSocket upgrade in the same process.

The consequence: after any browser request to the operator console, every charger frame resolved to the API request's already-released database client. Every BootNotification failed, the frame log stopped recording, and the process died. Two auditors reproduced it independently, deterministically, 6 times out of 6.

What this means for planning

A codebase with this much regulatory and protocol surface does not converge by inspection. It converges by adversarial reproduction, and the reproductions have to be re-run after every change. Budget for a fourth pass. The cost of finding the next one here is much lower than the cost of finding it on a customer's invoice.

03Things that would have wasted the vendor visit

  • 01
    The gateway died on any database error at connect or disconnect
    An uncaught promise rejection under Node 22's default --unhandled-rejections=throw. One transient error closed every other charger's socket on the box, and StartLimitBurst=5 means systemd stops restarting after the fifth.
    Fixed — and the process guards install after startup, so a genuine startup failure still exits rather than lingering as a zombie.
  • 02
    No DATABASE_URL a production process would start with
    As a superuser, the RLS posture check refuses to start. As plugsure_app, the gateway's boot-time CREATE SEQUENCE IF NOT EXISTS failed with permission denied — Postgres checks the ACL before IF NOT EXISTS short-circuits, so it failed on every start for a sequence that already existed. And the role was created NOLOGIN with no password, so the error's own advice could not be followed.
    Fixed — the stack now starts under NODE_ENV=production logging “row-level security is in force”, which it had never done before.
  • 03
    The documented production config refused every charger
    OCPP_TRUST_PROXY_PROTO is required for security profile 2 behind Caddy and appeared in no documentation, .env.example, compose file or systemd unit. The gateway logged a cheerful “listening” and answered 403 to everything.
    Documented — and the gateway now refuses to start in that combination rather than rejecting chargers silently.
  • 04
    The commissioning runbook could not be followed
    Two of its four steps named endpoints that did not exist, and the endpoint that actually moves a unit out of pending_adoption was never mentioned anywhere.
    Fixed — POST /v1/charge-points now exists, and all five documented steps were executed against a live stack.
  • 05
    A charger could adopt itself
    The station-level StatusNotification path wrote charge_point.status unguarded, so a unit could walk out of pending_adoption via a fault and back, then start producing billable sessions no operator had approved.
    Fixed — administrative state survives every connectivity and fault event.
  • 06
    A permanent 0 A ceiling on every idle charger
    ChargePointMaxProfile is persistent by design, so this is not a momentary instruction — it is a charger stranded at zero amps until the CSMS returns. A unit reporting Preparing deadlocked: held at 0 A it cannot energise, so it never reports Charging, so it is never allocated power.
    Fixed — floored at the station's idle share; zero only under explicit curtailment, and logged loudly when it happens.
  • 07
    Ordinary API calls destroyed the audit chain's tamper-evidence
    The MAC was computed over a body the database never stored — an undefined property hashes as null but is dropped by JSONB. One POST /v1/api-keys with the optional name omitted marked a tenant's entire seven-year log “broken”.
    Worse than useless: it trains an operator to ignore the one alarm that matters. Fixed and verified live.
  • 08
    npm ci was broken
    A @types/ws version that does not exist, blocking both documented deploy paths. Flagged as a known blocker for two audits without being fixed.
    Fixed. It installs.

05Retested and confirmed closed

Auditors were told not to trust a comment claiming something was fixed. In passes 2 and 3, several such comments were false.

Held up under attack

Privilege escalation via key issuance — platform:admin, unknown permission strings, nested arrays, prototype pollution and cross-org scoping all refused. Cross-tenant access on every route tried: frames, NDJSON export, site power, budget writes, Reset, session-by-id, QRIS checkout, foreign-site adoption — all 403 or inert. The SSE stream now fails closed. API keys whose base64url secret contains _ authenticate (this had silently killed roughly half of all issued credentials). The reply cache keys on action and payload, and never caches errors. The keyed audit chain detects mutation, truncation, reordering and forgery; head rollback and deletion are refused by database triggers. Offline replay ordered, shuffled and duplicated all bill exactly the delivered energy. 26 hostile frames answered spec-correctly with the socket never dropped. Forged X-Forwarded-For no longer changes req.ip. The Indonesian tax arithmetic — DPP nilai lain = 11/12 × price, PPN = 12% × DPP, PBJT before PPN — is correct, and the DPP stored is the one that goes on the faktur.

06What must happen before an Autel unit connects

  1. Set OCPP_MIN_SECURITY_PROFILE=2, OCPP_AUTO_ADOPT=false and OCPP_TRUST_PROXY_PROTO=true. At the default profile 0 there is no per-charger authentication at all — an unauthenticated peer can open a session as any tenant's charger and inject telemetry, and the API credential you hand the vendor does not constrain that in any way.
  2. Deploy under plugsure_app, not the database owner, so RLS is a real second line rather than a decorative one.
  3. Set AUDIT_HMAC_KEY and SECRETS_KEY — and keep them. Rotating the audit key stops every previously written entry from verifying.
  4. Run the commissioning sequence in the deployment runbook, and watch GET /v1/connection-attempts while the installer power-cycles the unit. Every attempt is recorded with its outcome, TLS state, offered subprotocols and whether credentials were presented — that log is what turns “it doesn't connect” into a one-line answer.
  5. Run a fourth audit pass. Three passes have each found real defects in the previous remediation.

07Deliberately still open

  • Never tested against real hardware. Every result here is against the simulator.
  • The payment provider is a mock. QRIS settlement and reconciliation against a real acquirer do not exist. Every prepaid session is now reconciled and the delta alerted, but there is no refund rail — an over-collection parks the session for a human.
  • OCPP 2.0.1 is modelled, not implemented. Only ocpp1.6 is advertised, deliberately: advertising a version you cannot speak is worse than not offering it.
  • PBJT's base and its position relative to PPN both need a tax advisor's sign-off. Both are configuration, both default to the reading we believe is correct, and both are flagged in the code.
